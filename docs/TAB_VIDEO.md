# 탭 영상에서 정답 탭 뽑기 — 설계 (2026-10-25)

목적: 기타 분리와 음 인식을 재려면 J-pop 정답이 필요하다(지금 0곡). 밴드스코어 PDF 는 비싸고 검증이 오래 걸리므로, 유튜브에 커버와 함께
탭을 보여 주는 영상에서 탭을 **음 데이터(마디 · 열 · 줄 · 프렛)** 로 뽑아 `bandscribe eval sheets` 의 실버 정답으로 쓴다.
결과는 지금 악보 JSON(`data/tmp/sheets_*/gtr1.json` 형식)과 같은 꼴로 내서 채점 코드를 그대로 쓴다.

## 0. 원칙

- **정확도를 재지 않은 추출은 정답으로 쓰지 않는다.** 공개 도구들(아래 출처)은 탭 화면을 PDF 그림으로 모으는 데서 멈추거나, 압축 영상의 프렛
  숫자 OCR 오류를 사용자가 찾을 수 없다고 적는다. 그래서 이 설계의 중심은 OCR 보다 **검증 관문**이다.
- 영상 · 프레임 · 뽑은 탭은 모두 `data/` 에만 둔다(커밋 금지). 탭은 영상 제작자의 채보다 — 개인 평가용으로만 쓰고 공유하지 않는다. 유튜브 다운로드의
  약관 위험은 이미 동의 기록(`data/config.toml [consent] youtube`)이 있지만, 영상(화면)까지 받는 것은 새 다운로드라 목록을 사용자가 승인한다.
- 실버 정답이다: 결속밴드 악보와 섞지 않고 따로 표를 만든다(`docs/decisions.md` 실버 규칙).

## 1. 영상의 종류 (처리 순서)

| 종류 | 화면 | 어려운 점 | 우선 |
|---|---|---|---|
| A. Guitar Pro · TuxGuitar · Songsterr 재생 화면 녹화 | 오선 + 탭, 커서가 움직이고 쪽이 넘어가거나 가로로 흐른다. 글꼴이 일정하다 | 쪽 보기에서는 반복이 펼쳐지지 않는다 → 커서 순서로 편다 | 1 |
| B. 직접 만든 탭 띠(영상 아래에 탭이 흐름) | 6줄 위 숫자, 가로 스크롤 | 글꼴 · 색이 제각각, 마디 번호 없음 | 2 |
| C. 손 · 지판 영상만(탭 없음) | — | 손 모양 인식이 필요 | 하지 않음 |

## 2. 처리 단계

1. **수집 목록** `data/eval/tabvid/videos.yaml` (로컬): 곡(작업 키), URL, 파트(gtr1 / gtr2 / bass / all), 튜닝 · 카포(사람이 한 줄 적는다 —
   머리말 OCR 보다 싸고 정확하다), 영상 종류, 메모. 후보는 yt-dlp 검색(`ytsearch`)으로 뽑아 사용자에게 보이고, 사용자가 고른 것만 받는다.
2. **받기:** yt-dlp(이미 있음)로 1080p 영상 + 오디오. 기존 YouTube 대기 간격을 지킨다.
3. **프레임:** ffmpeg 로 초당 2–4장, 앞 프레임과 거의 같은 것은 버린다(탭 영역 차이로).
4. **탭 줄 찾기:** 가로 투영(행별 어두운 화소 합)에서 같은 간격의 평행선 6개(베이스 4–5개)를 찾고 'TAB' 표시로 확인한다. numpy · scipy 만
   쓴다(OpenCV 없음).
5. **마디 · 열:** 세로 마디선으로 마디를 자르고, A 형은 마디 번호(위 왼쪽 숫자)로 마디를 식별한다. 숫자 덩어리의 x 위치로 열(같은 시각)을 묶는다.
   리듬은 1차에서 열 순서와 대략의 위치만 쓴다(지금 채점도 마디 안 음높이 묶음이다).
6. **글리프 읽기:** 줄 위 연결 성분을 0–24, x(뮤트), 그리고 h · p · / · \ · b · ~ · PM 같은 주법 표시로 분류한다. 분류기는 (a) 글꼴 템플릿 맞춤,
   부족하면 (b) GPU 환경 torch 의 작은 CNN. 학습 데이터는 7의 합성 영상에서 정답 라벨째 얻는다(새 다운로드 없음).
7. **같은 마디 여러 번 읽기:** 한 마디가 여러 프레임에 나오면 프레임별 읽기를 투표로 합치고, 갈리는 글리프는 '불확실'로 남긴다.
8. **연주 순서:** A 형은 재생 커서(색 막대 · 강조 상자)가 지나간 마디 순서 = 연주 순서라 반복이 저절로 펼쳐진다. 커서가 없으면 마디 번호 순서 +
   사람이 적은 반복 구조.
9. **출력:** 마디마다 numerator · 열 · (줄, 프렛, dead, tied) — 지금 악보 JSON 과 같은 형식. `data/eval/sheets/songs.yaml` 에 `truth: silver_video`
   로 올린다.

## 3. 검증 관문 (이게 통과해야 정답으로 쓴다)

1. **합성 영상으로 먼저 잰다(다운로드 없음):** 우리 `export/tab/score.gp`(정답을 아는 탭)를 뷰어(alphaTab)로 그려 Edge 헤드리스로 화면을 찍고,
   유튜브 비슷한 H.264 비트레이트로 다시 압축해 영상을 만든다. 거기서 뽑은 탭과 원래 탭을 비교하면 **글리프 정확도 · 마디 정확도**가 정확히 나온다.
2. **진짜 영상에서도 정답으로 잰다:** 결속밴드 6곡은 이미 PDF 악보 정답이 있다. 같은 곡의 탭 영상에서 뽑은 탭을 PDF 정답과 비교하면 실제 영상의
   추출 정확도가 나온다(채보자가 달라 생기는 차이는 마디 F1 로 따로 본다).
3. **영상 자기 소리와 대조:** 뽑은 탭을 소리로 만들어(뷰어의 탭 신스 · alphaTab) 영상 오디오와 마디별 크로마로 맞춘다. A 형 영상은 소리가 탭 재생인
   경우가 많아, 맞게 읽었으면 거의 일치한다. 낮은 마디는 '의심'으로 표시한다.
4. **프레임 투표 일치율, 글리프 신뢰도.**
5. **사람 확인:** 의심 마디만 영상 프레임과 뽑은 탭을 나란히 보여 준다(나중에 뷰어 화면).
- 통과 기준(사전 등록 예정): 합성 영상에서 글리프 정확도 99 % 이상, 마디 정확도 95 % 이상. 진짜 영상은 결속밴드 곡에서 PDF 정답과의 마디 F1 이
  같은 곡의 두 채보 사이 차이 수준. 곡마다 의심 마디 10 % 이하인 탭만 실버 정답으로 쓴다.

## 4. 단계와 비용

| 단계 | 내용 | 다운로드 | 비용 |
|---|---|---|---|
| P1 | 합성 영상 만들기(뷰어 → Edge 스크린샷 → ffmpeg), 줄 · 마디 · 글리프 읽기, 투표, JSON 출력. 합성에서 정확도 측정 | 없음 | CPU, 작업 1–2일 |
| P2 | 사용자가 고른 진짜 영상 3–5개(결속밴드 1–2곡 = 정확도 측정용, 怪獣の花唄 기타, 狭心症 베이스) | 영상 3–5개(승인) | CPU |
| P3 | 오디오 대조 관문, 의심 마디 표시 | 없음 | CPU |
| P4 | 곡 늘리기(사용자 목록), J-pop 실버 표 | 영상(승인) | — |

대안(쓰지 않음): 비전 언어 모델로 프레임을 읽는 방식(공개 도구 하나가 Claude vision API 를 쓴다)은 API 키와 비용이 들고, 로컬 모델은 6 GB VRAM
에 무겁다. 글꼴이 일정한 A 형에서 템플릿 · 작은 CNN 이 모자랄 때만 다시 본다.
